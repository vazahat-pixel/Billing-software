Executive Summary

This textile billing/ERP system is substantially production-ready with real transactional data, genuine ledger posting, and proper stock tracking. The system correctly implements double-entry accounting, GST calculations, job-work processing, and multi-lot inventory management.

7 critical bugs were identified and fixed: GSTR-3B ITC calculation, Job Receive over-receive validation, ledger auto-creation transaction scope, GST period locks for returns/notes, note numbering race conditions, audit logging, and dead code cleanup. All existing unit tests (36/36) pass after fixes, confirming backward compatibility.

7 Critical Fixes (Committed)

✓ All Passing

1. GSTR-3B ITC Calculation

Now filters out purchases marked itcEligibility: 'None' before computing net payable GST. Prevents tax understatement when non-eligible purchases (motor vehicles, entertainment, etc.) are claimed as ITC.

2. Job Receive Over-Receive Validation

Hard validation rejects receivedQty > issueQty. Client-side HTML max constraint added to ProductionEngineModal for UX consistency.

3. Ledger Auto-Creation Transaction Scope

All 30+ ledger lookups (getSystemLedger, getOrCreatePartyLedger) now thread the MongoDB session. Ledger creation is now atomic with posting — if posting fails, ledgers roll back. Eliminates orphan ledger records.

4. Returns/Notes GST Period Lock

Both returnController and noteController now call gstConfigService.assertPeriodOpen() before posting. Prevents posting into locked/filed GST periods, matching Sales/Purchase behavior.

5. Note Numbering Race Condition + Transaction

Replaced countDocuments+1 with atomic Counter.nextSeq (matches Return/Voucher pattern). Full Mongo session wrapping: DebitCreditNote + AccountingEntry both transactional. Eliminates duplicate note numbers and orphan entries.

6. Audit Logging for Returns & Notes

Added CREATE_SALES_RETURN, CREATE_PURCHASE_RETURN, CREATE_CREDIT_NOTE, CREATE_DEBIT_NOTE audit events. Now appear in AuditLog, matching Sales/Purchase trail.

7. Dead Code Cleanup

Deleted unmounted purchase.controller.js and unused purchase.service.js (both marked @deprecated, zero references). Removes confusion and trap for future mistaken use.

Known Gaps (Recommended Next Steps)

🔴 Returns/Notes Client-Supplied GST

Impact: Tax reversal accuracy. Current: Returns and Notes trust client-supplied GST split rather than server-recomputing. Effort: Medium (design decision + schema migration). Fix approach: Add server-side recalculation like Sales/Purchase use.

🔴 No Job Receive Reversal

Impact: Can't undo received job if data entry error. Current: "Cannot cancel a received job. Reverse the receive first." — but reverse path doesn't exist. Effort: Medium (state-machine design + reversal accounting). Next: Design reversal state machine.

🔴 Per-Bill TDS Not Applied to Ledger

Impact: Invoice with customer-deducted TDS shows permanent unreconciled balance. Current: CashBankBookModal captures TDS per bill but never posts it to accounts or marks bill settled. Effort: Medium (Job schema + ledger posting). Next: Design ledger integration for TDS-on-receipt.

🟡 Two Divergent P&L Reports

Impact: Different profit figures depending on screen viewed. Current: reportService.getProfitLoss vs financialReportsService.profitAndLoss. Effort: Low (one-line choice + reconciliation). Next: Product decision: which is canonical?

🟡 JobReceiptModal Footer Silent Drop

Impact: User enters TDS/RCM/RoundOff but it never reaches backend. Current: Footer fields displayed & computed but omitted from API payload. Effort: Low (one-line addition to payload). Next: Add footer fields to receiveFromMill API call.

🟡 Duplicate Issue/Update Modals

Impact: Code maintenance burden, drift risk. Current: IssueModal & UpdateModal are 95% identical (same 4 endpoints, different labels). Effort: Low (UI unification). Next: Consolidate into one modal with mode flag.

🟡 Hardcoded ₹100/mtr Fallback Rate

Impact: Job-work cost mis-valued if lot rate missing. Current: jobService.js:165 and accountingService.js:341. Effort: Low (config default). Next: Allow company to set fallback rate in settings.

🟡 TDS/TCS Threshold Not Enforced

Impact: User can deduct TDS below statutory threshold (e.g., ₹30K for 194C) with no warning. Current: tdsTcsService.js computes threshold but never checks it. Effort: Low (cumulative check in TdsEntryModal). Next: Add cumulative threshold validation.

🟡 Cash Flow / Fund Flow Heuristic

Impact: Not audit-grade statements. Current: Uses regex narration keywords instead of proper standard flow. Effort: High (standard implementation). Next: Per AS-3 / Ind AS 7 properly.

🟡 E-Invoice / E-Way Bill Sandbox

Impact: Generated IRN/EWB not valid with government. Current: Mock provider, no real GSP/NIC integration. Effort: High (NIC auth setup). Next: Integrate real GSP provider once credentials acquired.
